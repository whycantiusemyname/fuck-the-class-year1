## 5. 已修复的学习指导问题

### 5.1 解答泄露

根因在抽取脚本：

```text
D:\FuckTheClass\物理\90_缓存\s1-intake\学习指导\extract_learning_guide_qbank.py
```

旧规则只识别了很窄的解答起始：

```python
^(解|解法|答|答案)\b
```

这个写法有两个问题：

- 中文里 `\b` 对 `解（1）`、`解法一`、`解由`、`解因` 等不稳定。
- 书中的解答段还有 `分析`、`由题意`、`证明 由`、`所以`、`得当`、`合成波为` 等形式，旧规则没有覆盖。

因此，旧生成结果里混入了例题详解和习题指导推导，典型位置包括第 01、04、05、10、11、12、13、14、16、17、19 章的部分例题/习题。

本轮已把行首解答识别扩展，并重新生成题库。

### 5.2 OCR 损坏公式

原始 Markdown 中有形如：

```text
\left$$
$$ ^ {-1}
```

以及多行公式被拆成裸 LaTeX 的情况。旧脚本的 `normalize_math_noise()` 会去掉一部分坏分隔符，但没有把题面公式重新包回合法数学块，导致 validator 只给出“疑似裸数学表达”的 warning。

本轮对已知坏题号做了定点修复：

- 第 05 章 思考题 5-19

- 第 16 章 习题 16-10

## 6. 为什么之前没有在技能范围内修复

这件事本应属于 `$fuck-the-class` 的 S1 范围，因为 S1 明确规定题库只保留题面，解答归 S9。但之前没有修干净，原因是多层漏检叠加：

1. 官方 S1 validator 主要检查 metadata、LaTeX 分隔符、断链和标签一致性，不会语义判断“这段是不是解答”。
2. 之前的自定义检查只查了明显的 `解:`、`答:`、`答案:`，没有覆盖中文括号和“分析/由题意/所以”等教辅常见解答词。
3. 当时的修复重点放在非法 `question_form` 和 intake gate，被 validator 可见错误牵着走；validator 没把解答泄露升成 error。
4. 学习指导 PDF 的 final Markdown 本身混排“题目 + 答案 + 提示 + 解析”，S1 抽取脚本如果不专门识别这些中文解答标记，就会把解析误当题面。
5. 裸数学最初只是 path-level warning，没有给出 anchor 级定位；没有做本轮这种逐锚点扫描，就不容易定位到具体题号。

本轮已经把这部分修回 S1 技能范围内：脚本规则更新、题库重生成、S1 validator 通过、S1 intake manifest 重新绑定并验证通过。
