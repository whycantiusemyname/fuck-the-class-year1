## 5 分钟地图

三级模式 → E-R 概念建模 → 关系模型与完整性 → 关系代数 → SQL → 数据库设计、安全与维护。

## 题型分流

- 模式与模型：判断用户视图、逻辑结构或物理存储层。
- E-R 转关系：先标实体、码、联系和基数。
- 关系代数与 SQL：先列目标列、来源关系和连接条件。
- 控制与设计：先识别完整性、安全、并发、恢复或设计阶段。

## 第一动作

查询题先写目标列、来源表和连接条件；建模题先找实体、属性、联系与基数；约束题先标主码和外码。

## 最小自测

1. 外模式、模式和内模式各描述什么？
   - 答案要点：用户局部视图、全局逻辑结构、物理存储结构。
2. `WHERE` 与 `HAVING` 的对象有什么区别？
   - 答案要点：前者在分组前过滤行，后者对分组或聚合结果过滤。
3. 视图和索引有什么不同？
   - 答案要点：视图是查询定义的虚表；索引是加速访问的物理结构。
4. 多对多联系怎样转成关系？
   - 答案要点：建立独立关系，保存两端主码作为外码，并容纳联系属性。

## 提问入口

把一道 E-R 转换、关系代数或 SQL 题发给 tutor，并先写出你认为的主码、连接键和输出列。
