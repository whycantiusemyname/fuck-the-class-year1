# 第3章 软件工程方法 S10 启动卡

## 5 分钟地图

软件危机 → 瀑布/快速原型/智能模型 → 需求分析 → 软件设计 → 编码 → 面向对象方法 → 测试 → 维护。

## 题型分流

- 生命周期模型：判断需求稳定度与反馈方式，并区分瀑布、快速原型和教材智能模型。
- 结构化分析设计：区分 DFD、数据词典、模块结构和详细设计工具。
- 面向对象：先识别对象责任，再选 UML 视角。
- 测试维护：先判断测试层次、用例依据或修改原因。

## 第一动作

先判断情境处于哪个阶段、要交付什么产物，再用“做什么/怎么做/如何验证/为何修改”划清概念边界。

## 最小自测

1. 需求分析与软件设计分别回答什么？
   - 答案要点：需求回答系统做什么；设计回答系统怎样实现。
2. 白盒与黑盒测试依据有什么不同？
   - 答案要点：白盒依据内部逻辑与覆盖；黑盒依据功能规格与输入输出。
3. 环境变化导致的修改属于哪类维护？
   - 答案要点：适应性维护；修错是改正性，增强功能常属完善性。
4. 自顶向下与自底向上组装测试主要差在哪？
   - 答案要点：组合方向不同，前者常需桩模块，后者常需驱动模块。
5. 快速原型与智能模型的关注点有什么不同？
   - 答案要点：原型依靠可见模型与用户反复澄清需求；智能模型强调知识和智能支持。后者是否为考试主线待确认。

## 提问入口

把一个项目情境发给 tutor，让 tutor 先追问阶段、产物和约束，再判断模型、方法或维护类型。
