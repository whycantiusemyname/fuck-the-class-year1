## 本章主线

网络通过分层把复杂通信拆成可协作的协议功能：底层负责传输，高层提供端到端通信和应用服务。TCP/IP 是主线，IP 负责寻址和分组传送，TCP/UDP 提供不同传输语义，端口把数据交给具体进程；Socket 把协议能力变成程序接口。

## 课程用语与记号

- OSI 有七层，教材中的 TCP/IP 体系按四层理解。
- 电路、分组、混合、帧中继和 ATM 体现连接建立、传输单位与服务方式的不同取舍。
- TCP 面向连接、可靠、按字节流传输；UDP 无连接，开销小但不保证可靠交付。
- IP 地址定位网络接口，端口号区分主机上的应用进程。
- Socket 常见类型为流式 SOCK_STREAM 与数据报式 SOCK_DGRAM。
- 信息安全基本目标包括机密性、完整性和可用性。

## 方法与适用条件

- 协议归层题先判断功能对象：物理信号、链路帧、网络寻址、端到端传输还是应用服务。
- 子网题先由掩码区分网络位和主机位，再求网络地址、广播地址及可用主机范围。
- TCP 服务器基本流程为 `socket-bind-listen-accept-read/write-close`；客户端为 `socket-connect-send/recv-close`。
- 多字节整数跨网络传输时要考虑主机字节序与网络字节序转换。
- 防火墙实施边界访问控制，但不能单独解决所有内部威胁、恶意内容和端到端加密问题。
- FTP、邮件、DHCP、DNS 分别服务于文件传输、存储转发通信、自动配置和名称解析。
- 包过滤、代理、电路网关、规则检查和状态监视按所观察信息及转发方式区分。

## 题型信号与第一步

- 看到协议功能：先定位层次，再比较同层协议。
- 看到 TCP 与 UDP 选择：先判断可靠性、时延、连接和数据边界需求。
- 看到 IP/掩码：先写二进制或前缀长度，执行按位与得到网络地址。
- 看到 Socket 补流程：先判断服务端还是客户端、面向连接还是数据报。
- 看到安全方案：先明确要保护的目标与威胁，再选择加密、认证、访问控制或防火墙。
- 看到 SSH、IPSec、SSL：先说明保护场景和所在层次，再比较，不只背缩写。

## 易错边界

- HTTP 是应用层协议，HTML 是描述网页内容的标记语言。
- IP 提供尽力而为的分组交付，不等同于 TCP 的可靠传输。
- TCP 的“面向字节流”不保留应用消息边界，程序需要自行设计报文格式。
- 对称密码与公钥密码用途和代价不同；DES 与 RSA 不能只按“都能加密”混为一类。
