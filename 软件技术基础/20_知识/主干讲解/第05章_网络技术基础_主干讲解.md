# 第5章 网络技术基础：从分层通信到网络应用与安全

## 这一章抓什么

计算机网络把分散的主机连接起来，实现资源共享、数据传输和负荷分担。通信系统复杂到无法由一个协议完成，因此网络采用分层：每层向上提供服务、通过接口使用下层能力，并与远端对等层按协议协作。本章从网络类型、拓扑和 OSI 分层进入 TCP/IP、Internet 服务、Socket 编程、Web、网络安全以及物联网和移动互联网。

统一主线是“分层封装 → 地址定位 → 端到端传输 → 应用协议 → 编程接口 → 安全保护”。OSI 七层提供完整参考，TCP/IP 四层是实际 Internet 主线；Socket 把传输层能力暴露给进程，HTTP/HTML 等应用协议再建立具体服务。

## 先建立整体直觉

发送端把应用数据逐层加入控制信息，接收端逐层解释并交给上层。分层的好处是每层只关注自己的职责，物理介质改变不必重写应用，应用也不必直接处理比特传输细节。协议规定对等实体怎样交换，服务描述本层向上层提供什么。

> [!tip] 直觉
> IP 地址定位主机或网络接口，端口定位主机上的进程，域名给人提供易记名称，DNS 把名称转换成地址。完整通信端点不能只写 IP，也不能只写端口。

## 本章怎么串起来

网络功能与分类 → 拓扑和交换 → OSI 七层 → TCP/IP 四层 → IP 地址、端口与域名 → TCP/UDP → Internet 服务 → Socket 客户/服务器 → HTTP 与 HTML → 安全目标、防火墙和加密 → 物联网与移动互联网。

前半解释数据怎样跨网络到达，后半解释应用怎样使用通道以及怎样降低风险。每一层都有自己的地址、协议或接口，做题先定位层次。

## 分节主干

### 网络分层与交换

网络按范围可分局域、城域、广域和无线局域等，拓扑可有总线、星形、环形、网状。电路交换预先建立独占路径，分组交换把数据拆分后共享链路；不同方式在时延、利用率和控制上取舍。

教材还介绍混合交换、帧中继和 ATM 等组织方式，用来说明交换技术会在连接建立、分组长度和服务质量之间取舍。它们在当前课程中的考试地位尚未确认，但比较时应先看是否预先建立通路、信息以何种单位传送以及网络是否保留连接状态，而不是只背名称。

OSI 从下到上为物理、数据链路、网络、传输、会话、表示、应用层。TCP/IP 常概括为网络接口、网际、传输和应用四层。映射题应按职责对应，不要把七层名称硬塞成一一相等。

协议规定对等实体交换信息的规则，接口规定相邻层怎样调用，服务则是下层向上层提供的能力。发送端逐层封装控制信息，接收端逐层解封装；逻辑上是同层协议通信，实际数据仍沿本机层次和物理网络传送。把这三组关系分开，才能解释分层而不把“对等层”误认为直接相连。

### IP、TCP 与 UDP 分工

IP 提供无连接的网际传送并屏蔽底层网络差异。IPv4 地址由网络号与主机号组成，子网掩码用于区分网络部分；域名通过解析得到 IP。端口在本地主机上标识进程，TCP 与 UDP 端口空间相互独立。

TCP 提供面向连接、可靠的字节流，使用序号、确认和滑动窗口等机制。三次握手可理解为双方交换初始序号并相互确认，从而避免旧重复连接分组造成混乱。UDP 无连接、开销小但不保证可靠交付，应用必须根据需求选择。

子网计算先用子网掩码与 IP 地址逐位相与得到网络地址，再依据主机位确定同一子网范围。题目给出前缀长度时，要先换成网络位和主机位，不能把端口号混进地址计算。IP 数据报负责网际层传送，TCP 的滑动窗口则在端到端字节流中调节发送与确认，二者处理的对象不同。

> [!warning] 警惕
> “IP 无连接”与“TCP 面向连接”不矛盾，它们属于不同层。TCP 在 IP 提供的无连接分组服务之上建立端到端可靠性。

### Internet 服务和 Socket 编程

WWW 使用 HTTP 传输由 HTML 表达的超文本；TELNET 用于远程登录，FTP 传输文件，电子邮件采用延迟转发并使用 `Local-part@domain` 地址。接入配置可能通过 DHCP 自动获得，也可手工设置 IP、网关、子网掩码和 DNS。

这些服务共享 TCP/IP 基础，却有不同的应用语义。FTP 关注文件传输，电子邮件经邮件系统存储转发，DHCP 为主机提供地址和相关配置，DNS 把域名解析为地址。综合题应先说应用希望完成什么，再定位使用的服务和传输通道。

Socket 是进程通信端点。服务器通常依次执行 socket、bind、listen、accept、read/write 和 close，客户端依次执行 socket、connect、send/recv 和 close。流式 Socket 对应 TCP，数据报 Socket 对应 UDP。网络字节序转换用于避免不同主机表示差异。

流程题应先分清服务器和客户端，再按阻塞点理解：服务器 `accept` 等待连接，客户端 `connect` 主动发起；连接建立后双方才能按协议收发应用数据。

教材还介绍 Windows Socket 和 MFC 相关类，它们是同一套客户/服务器通信思想在特定编程环境中的接口包装。S8 主线保留通用调用关系；具体类名和界面操作是否考查尚待教师范围确认，不把平台细节提升为所有 Socket 程序都必须遵循的理论。

### Web 表达与服务

Web 服务器如 IIS、Apache 接收 HTTP 请求并返回资源。HTML 用标签组织标题、链接、表格和表单，XML 更强调可扩展的数据描述。HTTP 是通信规则，HTML 是内容表示，两者不能互换。网页题第一步应先确定结构与链接，再考虑样式或服务器部署。

一次网页访问可以把本章主线串起来：浏览器先通过 DNS 得到服务器 IP，再以临时端口连接服务器端口；若使用 TCP，连接建立后才发送 HTTP 请求。数据在发送端逐层封装，经网络传送，到服务器逐层解封装并交给 Web 服务，响应返回后浏览器解析 HTML，并可能继续请求图片、样式或脚本。

### 安全从目标、威胁和技术三层理解

网络安全目标包括可用性、保密性和完整性。威胁包括非法访问、病毒、隐蔽通道和拒绝服务。身份验证确认主体，访问控制限制权限，完整性机制检查数据是否被改动。

防火墙位于网络边界，可禁用不安全服务、进行地址转换、认证、预警与日志；类型包括包过滤、代理、电路网关、规则检查和状态监视。但防火墙不能自动解决内部人为失误、所有病毒或数据驱动攻击。

DES 是教材中的对称加密示例，RSA 为非对称加密示例；SSH、IPSec、SSL 分别在不同场景提供安全通信。学习时先确认技术位于何层、保护什么，再记端口或流程。

防火墙可按包过滤、代理、电路网关、规则检查和状态监视等方式实现边界控制。类型题应比较它观察的信息和转发方式；协议题则要区分 SSH、IPSec、SSL 所处的保护场景。对称密码和公钥密码在密钥使用与计算代价上不同，不能因为都能保护机密性就视为同一种机制。

### 物联网与移动互联网

物联网强调物物相连，教材把传感器、RFID 和嵌入式系统列为关键技术，并给出多种应用。移动互联网以移动终端、软件和应用构成环境，具有便携、泛在、永远在线、身份与定位关联、安全复杂等特点，并发展出 LBS、云计算等业务。

传感器负责感知，RFID 支持标识与识别，嵌入式系统在设备内部完成控制和处理；它们需要网络把数据送到应用。移动互联网则把终端移动性、位置和持续连接带入服务设计。教材案例用于理解技术构成，产品名称和发展趋势不作为超出教材的当前事实判断。

这些内容属于教材范围，但具体新平台和现状可能变化。S8 只保留教材定义、技术构成和应用逻辑，不把材料外的新产品或协议写成考试结论。

### 一道网络题怎样定位

协议题先问“这是哪一层的问题”：路由和 IP 属网际层，可靠端到端传输属于传输层，HTTP 属应用层。地址题先分域名、IP、子网掩码和端口。Socket 题画客户/服务器两条时间线，把 `listen/accept` 与 `connect` 对齐。安全题按“目标—威胁—措施—局限”组织答案。

### 沿一次通信把容易跳过的步骤补齐

拓扑选择先看故障范围和通信路径。总线结构简单但共享介质会形成共同故障点，星形便于集中管理但中心结点关键，环形按环路传递而单点故障可能影响全环，网状提供多路径但连接和管理成本高。交换方式则看是否先建立通路：电路交换建立后持续占用路径，分组交换让多个通信共享链路；帧中继、ATM 等内容的考试深度仍属范围待确认。

OSI 各层可沿数据单位理解：物理层传比特，数据链路层在相邻结点间组织帧，网络层负责跨网络寻址与路由，传输层提供端到端进程通信，会话层管理会话，表示层处理表示转换，应用层支持应用服务。IP 数据报首部中的版本、长度、标识与分片、TTL、协议、源和目的地址分别服务于解析、转发、分片生存和上层交付。

TCP 的可靠性来自序号、确认、超时重传和滑动窗口配合。发送方可在窗口内连续发送，确认到达后窗口前移；接收方用序号识别次序和重复。三次握手中，客户端发送初始序号，服务器回应自己的初始序号并确认客户端，客户端再确认服务器。第三次确认使双方都知道对方已收到自己的起始信息，不能压缩成“发三次包所以可靠”。

IPv4 地址题先把地址和掩码写成二进制或按前缀划线。网络地址为 IP 与掩码按位与；在通常子网题约定下，主机位全 $0$ 是网络地址、全 $1$ 是广播地址。DNS 把域名映射为地址；DHCP 则提供 IP、掩码、网关和 DNS 等配置，职责不同。

应用服务要按通信模型区分：TELNET 建立远程终端会话，FTP 围绕文件传输，电子邮件采用存储转发，WWW 用 HTTP 请求和响应取得资源。HTTP 请求包含方法、目标等信息，服务器返回状态与内容；HTML 描述页面结构，XML 描述可扩展数据。服务器部署或网页编辑器操作属于教材实例性内容，未获教师范围前不提升为必会平台步骤。

Socket 流程中的一次 `send` 不保证接收方一次 `recv` 恰好得到同一应用消息，因为 TCP 提供字节流而不是应用消息边界。应用层需规定长度字段、分隔符或固定长度。BSD Socket、Windows Socket 与 MFC 类的形态不同，但都围绕创建端点、绑定/连接、收发和关闭；若题目指定平台，再使用对应函数或类名。

安全题要沿风险选机制。认证回答“你是谁”，访问控制回答“你能做什么”，完整性保护回答“内容是否被改”，加密主要保护内容不被未授权理解。包过滤查看网络/传输层字段，代理代表应用通信，状态监视跟踪连接上下文。SSH 面向安全远程访问，IPSec 在 IP 层保护分组，SSL 为上层协议建立安全通道；它们保护位置不同。

物联网把传感、标识、嵌入式处理和网络传输串起来，移动互联网进一步引入移动终端、位置和持续连接。教材案例用于说明这一链条；材料外的新平台、新协议或市场趋势不据此改写课程结论。

## 解题流程

1. 定位网络层次和通信两端。
2. 地址题拆分 IP 网络/主机部分，并补端口或域名解析。
3. TCP 题画连接与确认顺序；UDP 题说明无连接及责任转移。
4. Socket 题分别列服务器、客户端调用和数据方向。
5. Web 题区分 HTTP、服务器与 HTML 内容。
6. 安全题先写保护目标，再匹配身份、控制、加密或防火墙，并说明局限。

## 易错点

- 把 OSI 七层和 TCP/IP 四层强行一一对应。
- 混淆 IP 地址、MAC 地址、域名和端口的职责。
- 认为 TCP 可靠就不依赖 IP，或认为 UDP 完全不能用于应用。
- 三次握手顺序和确认关系写乱。
- 服务器把 `connect`、客户端把 `listen` 当作起手。
- 把 HTTP 与 HTML 当成同一事物。
- 认为部署防火墙后内部错误、病毒和应用数据攻击都消失。
